Digital Planner sync reliability

12 August 2026
key findings
The production laptop cache and Supabase aggregate matched before mutation at the same revision, timestamp, and entity counts; no laptop unsaved payload was present.
The existing implementation rewrites the full normalized owner aggregate for every edit. The owner dataset has grown to 24 days, 50 written daily to-dos, 64 blocks, and 180 routine instances.
Supabase documents a maximum configurable timeout of 60 seconds for Dashboard and Client API queries. A 120-second function timeout therefore cannot guarantee that a slow client request survives.
Browser auth auto-refresh runs while the tab is foregrounded. Mobile background suspension therefore requires explicit foreground catch-up rather than reliance on a permanently live socket.
Realtime Postgres Changes is suitable as an invalidation prompt, but subscription errors and disconnects require a retry/catch-up path. Polling plus focus, visibility, and reconnect checks provide convergence even after a missed event.
A single owner-scoped JSONB document makes ordinary saves one row and retains atomic optimistic revision checks. Existing normalized tables can remain untouched as rollback protection.
